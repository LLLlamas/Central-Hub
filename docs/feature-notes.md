# Feature notes — shipped-feature deep detail

> Extends CLAUDE.md's "Recent additions" one-liners. Only features whose implementation detail isn't already covered by a dedicated CLAUDE.md section live here (Venue negotiation, Stage design media, Multi-tour architecture, Data modes, and Visibility model all have their own CLAUDE.md sections now — don't duplicate them below).

- **In-house PDF parser — TOC-driven** (`lib/pdfParser.ts` + `lib/pdfCore.mjs`) — no LLM, no backend. pdfjs-dist text extraction + positional reconstruction, Spanish and English riders. Exports: `parseRiderPdf(file) → RiderImport`, `parseFlightPdf(file, personnel) → FlightImport | null`, `parseHotelPdf(file, personnel, days) → { hotels, tasks }`, plus `renderPlotImagesFromUrl` and `extractPageText`. `lib/pdfCore.mjs` holds the pure algorithmic helpers (`groupRows`, `buildColMap`, `parseTocEntries`, `findHeadingPages`, `isPlotPage`, `classifyTocTitle`, etc.) shared between `pdfParser.ts` (browser) and `scripts/parse-rider.mjs` (Node CLI) — keep both in sync. **TOC drives sectioning:** `parseTocEntries` scores each early page by `^N. Title$` row count + monotonic numeric sequences; `findHeadingPages` then locates each entry's body heading (strict `^N- ALLCAPS$` first, then loose `^N. Title-Case$`); end pages = `Math.max(start, nextStart-1)`. Titles route via `classifyTocTitle` into typed extractors (`extractInputList`, `extractRooming`, `extractBackline`, `extractCatering`) or a free-text section. Any section range that would include the TOC page is clamped so structural pages don't leak into content. **Fallback:** if TOC parsing fails or yields <5 resolvable headings, `buildLegacySections` runs the old heading-regex pass. **Plot pages:** `isPlotPage(page)` flags pages with <8 text items, attached as `RiderSection.plots[]`. **Free text:** `RiderSection.pageTexts` + `extractPageText(page, { clipAboveY?, keepFromY?, headerBandPt?, footerBandPt? })` strips repeating page chrome and clips shared-page bounds. **Known quirks:** pdfjs-dist fragments Spanish accented chars (`producción` → `producci ó n`) — language detection uses unaccented function words; TOC titles preserved verbatim. **CLI:** `node scripts/parse-rider.mjs [path/to/rider.pdf]` writes `src/data/riderExtracted.json` for debugging. **Persistence:** `lib/riderPdfStore.ts` (`rider-pdfs` IndexedDB store, keyed `[tourId, RiderImport.id]`) stores every rider revision's bytes, not just the active one; a boot effect rehydrates missing `pdfObjectUrl`s from stored bytes. `lib/documentStore.ts` (`documents` store, same pattern) holds other binary attachments (hotel PDFs, stage-media uploads).

- **Shareable day sheet link** — "Share" on `/t/:tourId/daysheet/:date` and the print-preview action bar copies a tokenized URL (`/t/:tourId/print/daysheet/:date?token=…`) to the clipboard. `lib/shareToken.ts` generates + verifies mock base64 tokens. A valid token swaps "← Back to day sheet" for "Shared day sheet" and hides the day jumper. Recipients need the tour loaded in their own browser (local-storage backend) — real auth-gated sharing needs a server-issued + server-verified token.

- **Day-sheet Edit mode** — manager-only. The "Show clock" list becomes inline `EditableText`/`EditableSelect` fields via `ScheduleEditor` (in `DaySheets.tsx`, shared by desktop + mobile). Edits collect in local draft state and commit in one batch via Save/Discard (`updateScheduleItem` per dirty item → one history record each); invalid `HH:MM` or empty title blocks Save. **Add item** (`addScheduleItem`) and per-row **Delete** (`deleteScheduleItem`) mutate immediately. A "N edit events" disclosure renders `getScheduleItemHistory`. Time helpers live in `lib/time.ts` (`parseHHMM`/`fmtHHMM`/`isValidHHMM`, also used by `LobbyCallLadder`).

- **Printable day sheet** (`/t/:tourId/print/daysheet/:date`) — venue/promoter info from `data/venues.ts` (`getVenueForTour`). A new show city needs a venue entry there (or a `Tour.venues` override) or the print sheet's right column is empty.

- **Per-day lock state** — chips in DaySheets/Calendar/Overview; `lockedDays` + `dayLockHistory` (`DayLockRecord[]`, reason prompt) persist per-tour via `overlayStorage`, same as every other overlay.

- **Document submissions (Milestone 2)** — crew contribute documents without editing the tour directly. `/t/:tourId/me` (`MyTravelInfo`) is every member's personal page: their own flights/hotel/schedule/plots (filtered by `tourPersonId` + visibility) plus a "Submit a document" dropzone. A submission (`flight`/`hotel`/`document`/`other` + title + notes + optional file) is always **pending** — `proposeSubmission` records it (overlay bundle on `local`, `propose_submission()` RPC + `submissions` table + Storage on `supabase`). Managers review on `/t/:tourId/submissions` (`SubmissionsInbox`, manager-gated): **Approve** attaches the file as a `Document` and, for `flight`/`hotel`, routes it through `parseFlightPdf`/`parseHotelPdf` into the normal import flow; **Reject(reason)** discards it. AppState surface: `submissions`, `refreshSubmissions`, `proposeSubmission`, `approveSubmission`, `rejectSubmission`, `loadSubmissionFileUrl`, `addDocument`.

- **Plots** (`/t/:tourId/plots` + the Rider Builder's own Plots tab) — a thumbnail grid of every plot image the parser extracted (stage plot, lightplot sheets), reusing `SectionPlotCard` + `PlotImageLightbox` (fullscreen, arrow-key nav) + `collectPlotsBySection`, all exported from `RiderBuilder.tsx`. Plot images live at `RiderSection.plots[]` (`{ page, caption, kind, dataUrl?, width?, height? }`), rendered as PNGs from the source PDF via pdfjs canvas (scale 2x) — **not persisted to localStorage** (base64 would blow quota); a boot effect re-derives them from the source PDF whenever a restored tour is missing them.

- **Gear & Supplies tracker** (`/t/:tourId/gear`) — flat inventory seeded from an *imported* rider only (`buildRiderGearItems()` in `data/gearFixture.ts`, ~80 items from Input List/monitors/backline/video/dressing rooms/catering; skipped entirely for an authored rider, see CLAUDE.md's Data modes). `GearItem`: name, quantity, unit, category, status (`needed/sourced/confirmed/not_required`), `providedBy`, `estimatedCost`, `fromRider`. **Re-import smart merge:** `mergeGearItems()` keeps user edits (status/cost/notes) on name-matched items, updates quantities, appends new items, keeps items that disappeared from the new rider. Manual items (`fromRider: false`) are always untouched. UI: category sidebar + status filter + search, grouped/collapsible table, click a status badge to cycle, running cost summary bar.

- **Cmd+K palette** — provider in `Layout`, tour-scoped search index (days, personnel, schedule items, venues, pages) built via `tourPath`.
- **Route map** — static SVG, city coordinates in `lib/mapProjection.ts` (shared with `MyToursMap`). New cities need their lat/lng added there.
- **Calendar List/Grid toggle** — defaults to Grid on desktop, List on mobile, switchable on both.
- **Lobby-call ladder** — only renders for show days, anchored on the `doors` schedule item; empty state if missing.

## Ingest deep detail (route CSV, hotels, dormant flights)

`web/public/` holds the uploadable fixtures a new tour is built from: the rider PDF, `sample-tour-route-mexico-7day.csv` (7-day Mexico route), `sample-travel-grid-mexico.csv` (travel-agent grid, dormant while `FLIGHTS_ENABLED` is false), per-flight e-ticket PDFs (dormant, same reason), and two per-hotel booking-confirmation PDFs. Generated by `scripts/gen-flight-pdfs.mjs` (`pdf-lib`, dev-only) — re-run it if `flightFixture.ts`/`hotelFixture.ts` data changes. Keep the parser anchor labels (`BOOKING REFERENCE / FLIGHT / DEPART / ARRIVE / NAME / SEAT`, `HOTEL / CHECK-IN / CHECK-OUT / NIGHTS / ROOMING LIST / GUEST / ROOM`) in sync with `parseFlightPdf`/`parseHotelPdf` if the PDF layout changes.

**Hotels — one PDF per hotel, direct import.** `/t/:tourId/ingest/flights`'s "Hotels & rooming" section is a multi-file dropzone; each file routes through `parseHotelPdf` (or the fixture fallback by filename) into one `Hotel` + that hotel's advance `Task`s via `addHotelImportToScratch`. No review/approve step.

**Re-upload = "Updated" audit semantics.** Route and hotel steps re-open their dropzone in place via a **Re-upload** toggle; a new file replaces the live data and bumps `UpdateStamp.updates`, flipping the audit line from "Imported by X" → "Updated by X". Each re-upload pushes the previous stamp into `Tour.routeImportHistory[]`/`Tour.hotelImportHistory[]`, surfaced as collapsible history panels in `FlightIngest`.

**Flights (dormant behind `FLIGHTS_ENABLED`)** — two import paths feed one review queue: the travel-agent grid CSV (`lib/travelGridCsv.ts`, one `FlightImport` per leg) and per-flight PDFs (one per file). Duplicate detection (`findFlightDuplicates` on airline+flightNumber+departDate) offers **Replace** or **Merge**; an additive-only merge (new passengers, no seat/metadata changes) on an already-committed import patches Travel directly without dropping back to review. Unmatched passenger names get per-row Assign/Add-new/Skip resolution (`flightPassengerResolutions`, keyed `${importId}::${name.toLowerCase()}`). **Discard** (`discardFlightImport`) removes the import, its Travel records, and any pending resolutions.

## Visibility deep detail

> Seed policy, save-cascade-by-type, and the defaults-editor mechanics are covered in CLAUDE.md's "Visibility model" — this section is UI-implementation detail only.

`components/VisibilityEditor.tsx` (non-compact mode): a right-aligned **Set-all** row of three colored circles sets the floor for every group at once and wipes overrides, except the pinned `grp_mgmt`/`grp_production` rows (`PINNED_GROUP_IDS`), which sit above it and survive the bulk action. Rows with no override show a soft-highlighted floor value with an "inherited from floor" tooltip. Group rows expand to tags + members, each with its own picker. On `/t/:tourId/schedule`, sidebar rows get three visual cues: the active+edited row gets a dark green background (inline style — Tailwind's arbitrary-hex scanner misses it), any item with a saved edit gets a soft green tint, and every other item of the selected type gets a tan tint to preview the save-cascade scope. `PermissionsStatus` tracks `configured / total` schedule-item types and lists what's left; clicking a type jumps the editor to its first item.
